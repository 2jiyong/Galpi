# 갈피 MVP 기능 명세

- 작성일: 2026-11-13
- 기준 문서: [PROJECT_PLAN.md](../../../PROJECT_PLAN.md), [ARCHITECTURE.md](../../../ARCHITECTURE.md)
- 상태: 초안. `(내 판단)` 표시 항목은 검토가 필요한 기본값

## 0. 이 문서의 목적

기획서는 갈피를 **왜**, **무엇을** 만드는지 설명한다. 이 문서는 MVP가 **정확히 어떻게 동작하는지** 정해서, 백엔드 유스케이스·API·화면을 이 문서만 보고 구현할 수 있게 한다.

MVP의 목표는 기획서 11장의 질문(갈피를 자연스럽게 만드는가, 문장을 꾸준히 쌓는가, 필요한 순간 다시 여는가)에 답하는 것이다. MVP 사용자는 만든 사람 본인 한 명이다.

## 1. 결정 사항

| 항목 | 결정 |
|---|---|
| 사용자 | 본인 한 명만 쓴다. 계정 기능은 없다 |
| 플랫폼 | 서버에 배포하는 모바일 웹. PWA로 홈 화면에 추가할 수 있다 |
| 접근 제한 | 비밀번호 하나로 잠근다 |
| 문장/팁 | 구분하지 않고 둘 다 "문장"으로 다룬다. 어떤 성격인지는 어느 갈피에 담았는지로 드러난다 |
| 최근 본 갈피 | MVP에 포함한다 |
| 고정 | 별도 기능을 만들지 않는다. **즐겨찾기한 문장이 목록과 집중 보기에서 맨 위로 온다** |
| 빠른 실행 | 다음 버전으로 미룬다 |
| 순서 직접 변경 | 다음 버전으로 미룬다. `display_order` 컬럼은 남겨 두고 0으로 둔다 |
| 무작위 보기 | 홈에서는 전체 갈피에서, 집중 보기에서는 현재 갈피 안에서 뽑는다 |
| 알림, 행동 기록 | MVP에서 뺀다 |

## 2. 도메인 규칙

기존 `Galpi.java`, `Phrase.java`, `V2__create_galpis_and_phrases.sql`의 규칙을 그대로 따른다.

**갈피**
- 제목: 앞뒤 공백을 제거한 뒤 1~50자, 필수
- 설명: 앞뒤 공백을 제거한 뒤 0~200자. 비어 있으면 `null`로 저장한다
- 갈피를 지우면 안의 문장과 출처도 함께 지워진다

**문장**
- 내용: 앞뒤 공백을 제거한 뒤 1~500자, 필수
- 출처: 0~10개, 각 1~200자. 입력 순서를 유지하고, 중복된 출처는 하나로 합쳐진다
- 즐겨찾기 여부(`favorite`)를 가진다
- 문장을 다른 갈피로 옮길 수 있다. **현재 `Phrase`에는 갈피를 바꾸는 메서드가 없다.** 도메인을 분리할 때 추가한다

## 3. 기능별 동작과 완료 기준

### 3.1 갈피 CRUD
- 갈피를 만들고 고칠 때 제목과 설명을 입력한다. 검증에 실패하면 해당 필드 아래에 오류를 표시한다
- 삭제 전에 "문장 N개도 함께 삭제됩니다" 확인 창을 띄운다
- 목록은 만든 순서로 보여 준다. (내 판단) 오래된 갈피가 위, 최신 갈피가 아래다
- 갈피가 하나도 없으면 홈에 "첫 갈피를 만들어 보세요" 안내와 만들기 버튼을 보여 준다

### 3.2 최근에 본 갈피
- 갈피 상세 화면이나 집중 보기에 들어가면 그 갈피의 `last_viewed_at`을 현재 시각으로 갱신한다
- (내 판단) 홈 맨 위에 `last_viewed_at`이 최신인 갈피를 최대 3개 보여 준다
- 한 번도 본 갈피가 없으면 이 영역을 숨긴다

### 3.3 문장 CRUD
- 입력 항목: 내용, 출처(0~10개, 줄 단위로 추가·삭제), 저장할 갈피(기본값은 지금 보고 있는 갈피)
- 갈피 안 문장 목록은 **즐겨찾기한 문장 먼저**, 그 안에서는 만든 순서대로 정렬한다
- 삭제 전에 확인 창을 띄운다
- 저장할 갈피를 바꾸면 문장이 그 갈피로 옮겨진다

### 3.4 즐겨찾기
- 문장 목록과 집중 보기 양쪽에서 켜고 끌 수 있다
- 켜면 그 문장이 갈피 안 목록과 집중 보기 순서의 맨 앞쪽으로 온다
- (내 판단) 갈피를 넘나드는 "즐겨찾기 모아 보기" 화면은 MVP에 넣지 않는다

### 3.5 집중 보기
- 화면 가운데에 문장 하나를 크게, 출처는 그 아래에 작게 보여 준다
- 이전/다음 버튼과 모바일 좌우 스와이프로 넘긴다. "n / 전체" 위치를 표시한다
- 처음과 끝에서 더 넘기면 멈춘다. (내 판단) 처음으로 되돌아가지 않는다
- 시작 위치는 정렬된 목록의 첫 문장이다. 목록에서 특정 문장을 눌러 들어오면 그 문장부터 보여 준다
- 섞기를 켜면 현재 갈피 안의 문장 순서를 무작위로 섞는다. 같은 문장이 연달아 나오지 않는다. 끄면 원래 순서로 돌아간다
- 즐겨찾기 토글과 닫기(갈피 상세로 돌아감)가 있다
- 문장이 0개인 갈피에서는 "집중해서 보기" 버튼을 비활성화하고 "문장을 먼저 추가해 보세요"를 안내한다

### 3.6 홈의 무작위 문장
- 전체 문장 중 하나를 카드로 보여 주고, 그 문장이 속한 갈피 이름을 함께 표시한다
- 갈피 이름을 누르면 그 갈피 상세로 이동한다
- "다른 문장" 버튼을 누르면 직전 문장을 빼고 다시 뽑는다. 문장이 하나뿐이면 같은 문장을 보여 준다
- 문장이 하나도 없으면 이 영역을 숨긴다

### 3.7 비밀번호 잠금
- (내 판단) 서버 환경변수 `APP_PASSWORD`와 비교한다. 값이 설정되지 않으면 서버가 시작하지 않는다
- (내 판단) 로그인에 성공하면 세션 쿠키(HttpOnly, Secure, SameSite=Lax)를 발급하고 30일 동안 유지한다. 운영은 HTTPS를 전제로 한다
- 로그인하지 않은 상태의 `/api/**` 요청은 401을 받는다. 프론트는 401을 받으면 로그인 화면으로 보낸다
- `/api/health`, `/actuator/health`, 로그인 API, 정적 화면은 로그인 없이 열린다
- (내 판단) 로컬 개발에서는 기본 비밀번호를 `.env.example`에 둔다

### 3.8 PWA
- (내 판단) manifest와 아이콘을 넣어 휴대폰 홈 화면에 추가하면 앱처럼 열리게만 한다
- 오프라인 지원(서비스 워커 캐시)은 넣지 않는다

## 5. API

모든 경로는 `/api` 아래에 있고 JSON을 주고받는다.

| 메서드 | 경로 | 설명 |
|---|---|---|
| POST | `/api/auth/login` | `{ "password" }`. 맞으면 세션 발급 204, 틀리면 401 |
| POST | `/api/auth/logout` | 세션 종료 204 |
| GET | `/api/auth/me` | 로그인 상태면 204, 아니면 401 |
| GET | `/api/galpis` | 갈피 목록. 항목마다 `id, title, description, phraseCount, lastViewedAt, createdAt` |
| POST | `/api/galpis` | `{ "title", "description" }` → 201 + 생성된 갈피 |
| GET | `/api/galpis/{id}` | 갈피 단건 |
| PUT | `/api/galpis/{id}` | 제목과 설명 수정 |
| DELETE | `/api/galpis/{id}` | 삭제(문장 포함) 204 |
| POST | `/api/galpis/{id}/views` | `last_viewed_at` 갱신 204 |
| GET | `/api/galpis/{id}/phrases` | 정렬된 문장 목록. 항목마다 `id, galpiId, content, sources[], favorite, createdAt` |
| POST | `/api/galpis/{id}/phrases` | `{ "content", "sources" }` → 201 |
| PUT | `/api/phrases/{id}` | `{ "content", "sources", "galpiId" }`. `galpiId`가 바뀌면 이동 |
| DELETE | `/api/phrases/{id}` | 삭제 204 |
| PUT | `/api/phrases/{id}/favorite` | `{ "favorite": true }` |
| GET | `/api/phrases/random?excludeId=` | 전체에서 무작위 1개와 `galpiTitle`. 문장이 없으면 204 |

**오류 응답**
- 400: 검증 실패. `ProblemDetail`에 필드별 메시지를 담는다
- 401: 로그인 필요
- 404: 갈피나 문장이 없음. 존재하지 않는 `galpiId`로 옮기려 할 때도 404

집중 보기의 섞기는 프론트에서 처리한다. 갈피의 문장 목록을 이미 받아 두므로 별도 API가 필요 없다.

## 6. 스키마 변경

- `V3__add_galpi_last_viewed_at.sql`
  ```sql
  ALTER TABLE galpis ADD COLUMN last_viewed_at TIMESTAMP WITH TIME ZONE;
  ```
- 그 밖에는 바꾸지 않는다. `favorite`, `display_order`는 지금 그대로 쓴다

## 7. 범위 밖

MVP에서 만들지 않는 것:

- 빠른 실행, 문장 고정, 순서 직접 변경, 즐겨찾기 모아 보기
- 알림, 행동 기록, 통계
- 오프라인 지원
- 계정, 공유, 친구, 커뮤니티, AI 추천
- 배포 플랫폼 선택. 구현 막바지에 따로 정한다

## 8. 구현 순서

1. 도메인과 JPA 분리 ([ARCHITECTURE.md](../../../ARCHITECTURE.md)). 이때 `Phrase`에 갈피 이동 메서드를 추가한다
2. 갈피 CRUD를 화면까지 완성한다. V3 마이그레이션과 최근 본 갈피를 포함한다
3. 문장 CRUD와 즐겨찾기
4. 집중 보기와 홈의 무작위 문장
5. 비밀번호 잠금, PWA, 배포
